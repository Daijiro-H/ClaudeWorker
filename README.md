# S&P500 RSI Notifier

S&P500(^GSPC)の日足終値からRSI(14)を計算し、毎日LINE公式アカウント(Messaging API)で通知するツールです。
RSIが70以上(買われすぎ)または30以下(売られすぎ)になった場合は、通知内にアクション検討のシグナルを表示します。
また、RSIが40以下になった場合は「売られすぎゾーンに接近」の要注意シグナルも表示します。

(LINE Notifyは2025年3月31日にサービス終了したため、後継のMessaging APIを使用しています。)

## 仕組み

- `scripts/check_sp500_rsi.py` が yfinance で S&P500 の直近の終値を取得し、Wilder方式のRSI(14)を計算します。
- 結果は毎回通知されます(RSIが70/30に到達したかどうかにかかわらず)。通知の仕組みは
  PLTRツールと共通で、`scripts/notify.py` に実装されています。詳細は後述の
  「PLTR $160 Notifier」の[通知経路](#通知経路)を参照してください。
- GitHub Actions のスケジュール実行 (`.github/workflows/daily-rsi-check.yml`) により、平日22:30 UTC(米国市場のクローズ後)に自動実行されます。

## データの鮮度

Yahooは引け後しばらくの間、最新セッションを**2か所で食い違った状態**で返します。
日足の配列にはその日の行が存在するものの **OHLCがnull** のままで、
確定した終値は隣のリアルタイム相場(`meta`)側にあります。

```
download period=1mo -> [('09-01', 179.92), ('09-02', 169.46), ('09-03', nan)]
chart meta          -> regularMarketPrice=182.53, regularMarketTime=2026-09-03T20:00:00Z
```

このnull行を捨てると前営業日まで遡ってしまい、実際に2026-09-03と2026-09-04の実行は
前日と同一の値を配信していました(Yahooのサイトには最新値が表示されていたにもかかわらず)。

現在は `scripts/market.py` が以下を行います。

- 米国東部時間で16:00のクローズを過ぎた直近の平日を「本来あるべきセッション」として算出
- 最新セッションの日足がnullの場合、**捨てずにリアルタイム相場から補完**します
  (終値と当日の高値・安値を、`regularMarketTime` が示すセッション日で記録)
- 補完は**そのセッションが「本来あるべきセッション」と一致する場合のみ**行うため、
  取引時間中のセッションが確定値として記録されることはありません
- どちらの経路にも該当セッションが無い場合は45秒間隔で最大3回まで再取得し、
  それでも無ければ**古い値を黙って配信せず**、件名に `※データ遅延`、
  本文に未反映のセッション日を明記します

```
[PLTR] $179.92 — $160 未到達 (あと $19.92 / 12.4%) ※データ遅延
```

判定は平日ベースのため、米国市場の**休場日**にもこの表示が出ます。古い値を最新であるかのように
見せるより、遅延の可能性を伝える方を優先しています。

## セットアップ

### 1. LINE公式アカウント(Messaging APIチャネル)の作成(任意)

1. [LINE Developers Console](https://developers.line.biz/console/) にログイン(お持ちのLINEアカウントでOK)
2. プロバイダーを作成(未作成の場合)し、「新規チャネル作成」から **Messaging API** チャネルを作成
3. 作成したチャネルの `Messaging API設定` タブで **チャネルアクセストークン(長期)** を発行
4. 同じくチャネルの `Messaging API設定` タブに表示されるQRコードから、通知を受け取りたいLINEアカウントでBotを友だち追加
5. `チャネル基本設定` タブ下部の「あなたのユーザーID」を確認(自分宛てにpushする場合のユーザーIDとして使用可能)

### 2. GitHub Secrets への登録(任意)

**LINE通知が不要なら、この手順は不要です。** GitHub Issueによる通知はSecretsなしで動作します。
LINEでも受け取りたい場合のみ、リポジトリの `Settings > Secrets and variables > Actions`
で以下のSecretを登録してください。

| Secret名 | 内容 |
| --- | --- |
| `LINE_CHANNEL_ACCESS_TOKEN` | 発行したチャネルアクセストークン(長期) |
| `LINE_USER_ID` | 通知を送りたいLINEアカウントのユーザーID |

### 3. 動作確認

`Actions` タブから `Daily S&P500 RSI Check` ワークフローを選択し、`Run workflow` で手動実行して通知が届くことを確認してください。

## ローカル実行

```bash
pip install -r requirements.txt
export LINE_CHANNEL_ACCESS_TOKEN=xxxxxxxx
export LINE_USER_ID=Uxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
python scripts/check_sp500_rsi.py
```

## 通知の例

```
S&P500 RSIチェック
日付: 2026-08-04
終値: 5,432.10
前日終値: 5,389.44 (2026-08-03)
前日比: +42.66 (+0.79%)
RSI(14): 72.3
シグナル: 買われすぎ(RSI >= 70) -> 売りアクション検討
```

## カスタマイズ

- RSI期間やしきい値は `scripts/check_sp500_rsi.py` 冒頭の `RSI_PERIOD` / `OVERBOUGHT` / `OVERSOLD` / `CAUTION_LOW` で変更できます。
- 実行時刻は `.github/workflows/daily-rsi-check.yml` の `cron` を変更してください(UTC指定です)。

# PLTR $160 Notifier

Palantir(PLTR)の株価が **$160 に到達したか** を毎朝チェックして通知するツールです。
PLTRは$160より上で推移しているため、「下落して$160に到達したか」を判定します。

## 仕組み

- `scripts/check_pltr_price.py` が yfinance で PLTR の直近の日足を取得し、終値・高値・安値を確認します。
- 判定条件: **終値が$160以下**、または **その日の安値が$160を割り込んだ** 場合に「到達」とします(ザラ場で一時的に到達したケースも拾います)。
- GitHub Actions のスケジュール実行 (`.github/workflows/daily-pltr-check.yml`) により、毎日 23:00 UTC(= 翌朝 **8:00 JST**、米国市場のクローズ後)に自動実行されます。

## 通知経路

このツールは通知経路を2つ持ちます。**設定なしで動くのはGitHub Issueの方です。**

| 経路 | 送信タイミング | 必要な設定 |
| --- | --- | --- |
| **GitHub Issue** | $160に到達したときのみ | **不要**(`GITHUB_TOKEN` を自動使用) |
| LINE Messaging API | 毎日(到達・未到達どちらも) | `LINE_CHANNEL_ACCESS_TOKEN` / `LINE_USER_ID` |

$160に到達するとリポジトリにIssueが自動作成され、GitHubからオーナー宛にメール通知が飛びます。
Secretsの登録は不要で、これがこのツールの主たるアラート経路です。

Issueは作成時に**オーナーへの担当者割り当てと@メンション**を行います。
リポジトリのWatch設定が既定の「Participating and @mentions」の場合、
自分が関与していないIssueは通知対象外になるためです。
割り当てとメンションによって「Participating」に該当し、Watch設定を
「All Activity」に変更しなくても通知が届きます。
宛先を変更したい場合は、ワークフローの `ISSUE_ASSIGNEE` を書き換えてください。

LINEのSecretsが未設定の場合、LINE送信は警告を出してスキップされるだけで、**ワークフローは失敗しません**。
GitHub Issueによる通知はそのまま機能します。

判定結果は到達・未到達にかかわらず、毎回 GitHub Actions の **ジョブサマリー** にも出力されます
(`Actions` タブの各実行結果ページで確認できます)。

## セットアップ

### 必須: 既定ブランチへのマージ

GitHub Actions のスケジュール実行(`on: schedule`)は **リポジトリの既定ブランチ上のワークフローしか起動しません**。
このブランチをマージするまで、毎朝の自動実行は始まりません。マージ前に動作を試す場合は
`Actions` タブから `Daily PLTR $160 Check` を選び、`Run workflow` で手動実行してください。

### 任意: LINE通知を有効にする

毎日LINEでも受け取りたい場合のみ、`Settings > Secrets and variables > Actions` に以下を登録してください
(S&P500 RSIツールと同じSecretsを共用します)。

| Secret名 | 内容 |
| --- | --- |
| `LINE_CHANNEL_ACCESS_TOKEN` | チャネルアクセストークン(長期) |
| `LINE_USER_ID` | 通知を送りたいLINEアカウントのユーザーID |

## ローカル実行

```bash
pip install -r requirements.txt
python scripts/check_pltr_price.py
```

Secretsなしでも実行でき、判定結果が標準出力に表示されます。

## 通知の例

```
PLTR $160 チェック
日付: 2026-08-27
終値: 158.40
前日終値: 169.46 (2026-08-26)
前日比: -11.06 (-6.53%)
高値: 162.00 / 安値: 155.00
判定: 到達($160以下) -> アクション検討
```

## カスタマイズ

- しきい値は `scripts/check_pltr_price.py` 冒頭の `DEFAULT_THRESHOLD` で変更できます。
- 一時的な上書きは、`Run workflow` の `threshold` 入力(環境変数 `PLTR_THRESHOLD`)で行えます。
  高い値(例: `999`)を指定すると必ず「到達」と判定されるため、**通知が実際に届くかのテスト**に使えます。
- 銘柄は同じく `TICKER` で変更できます。
- 実行時刻は `.github/workflows/daily-pltr-check.yml` の `cron` を変更してください(UTC指定です。JSTから9時間引いた値になります)。

# Market Stress Composite Notifier

3つの指標を **「逆張り的ストレスが強いほど高い」向きに0〜100へ正規化** して加重平均し、
合成スコアが **65を超えたら逆張り(買い)シグナル** として毎営業日通知するツールです。

| 指標 | 重み | 正規化 |
| --- | --- | --- |
| CNN Fear & Greed Index | **40%** | `100 - 指数`(指数0=Extreme Fear → ストレス100 / 指数100=Extreme Greed → ストレス0) |
| VIX | **30%** | 12以下=0 / 40以上=100 の線形(範囲外はクランプ) |
| S&P500の200日線からの乖離 | **30%** | +10%以上=0 / **0%(200日線上)=50** / -10%以下=100 の線形 |

3指標とも **中立な相場がおよそ50点** になるよう中心を揃えてあります
(Fear & Greed 50、VIXバンドの中点、株価が200日線上)。
したがって「65超」は、どれか1つが跳ねただけではなく、
**加重平均として中立から明確にストレス側へ振れている状態** を意味します。

参考として、実際のスコアの出方は次の通りです。

| 相場 | Fear & Greed | VIX | 200日線乖離 | スコア | 判定 |
| --- | --- | --- | --- | --- | --- |
| 平穏な上昇 | 75 | 13 | +8% | 14.1 | 平常 |
| 中立 | 50 | 26 | 0% | 50.0 | 平常 |
| 軽い押し目 | 30 | 22 | 0% | 53.7 | 平常 |
| 本格的な調整 | 20 | 28 | -4% | 70.1 | **シグナル** |
| パニック | 10 | 38 | -9% | 92.4 | **シグナル** |

## 仕組み

- `scripts/check_market_stress.py` が3指標を取得し、正規化・加重平均してスコアを算出します。
- Fear & Greed は CNN のダッシュボードが使うJSONフィード
  (`scripts/fear_greed.py`)から取得します。公開APIではないため、
  ブラウザ相当のUser-Agentを付け、日付なしURLが404を返す場合に備えて
  日付付きURLへのフォールバックと最大3回の再試行を行います。
- VIX(`^VIX`)とS&P500(`^GSPC`)は他のツールと同じ `scripts/market.py` 経由で取得するため、
  後述の[データの鮮度](#データの鮮度)の補完・遅延表示がそのまま効きます。
  200日移動平均のため、S&P500は2年分の日足を取得します。
- 結果は毎回通知されます(65超かどうかにかかわらず)。通知経路はPLTR/RSIツールと共通で、
  `scripts/notify.py` に実装されています。
- GitHub Actions のスケジュール実行 (`.github/workflows/daily-market-stress-check.yml`) により、
  平日 23:30 UTC(= 翌朝 **8:30 JST**)に自動実行されます。

## 一部の指標が取得できなかった場合

3指標は **CNNとYahooという独立した2系統** から取得するため、片方だけ落ちることがあります。
取得できなかった指標は **0点(=ストレスなし)として扱わず、計算から除外** し、
**残った重みで再正規化** します。スコアの意味が変わらないようにするためです。

```
[市場ストレス] 75.6 — 65超 逆張り検討 ※一部データ欠損
...
  Fear & Greed (40%): 取得失敗(CNNに接続できず) -> 除外
  VIX (30%): 31.50 / 2026-09-16 -> ストレス 69.6 -> 寄与 20.9
  S&P500 200日線乖離 (30%): 5,400.00 / MA200 5,762.93 (-6.30%) -> ストレス 81.5 -> 寄与 24.4
※取得できた 60% 分の重みで再正規化したスコアです(欠損分は0点扱いにせず除外しています)
```

件名には `※一部データ欠損` が付き、本文にどの指標がなぜ欠けているかが明記されます。
**3指標すべてが取得できなかった場合のみ**、スコアを出さずにワークフローが失敗(exit 1)します。


## 通知の例

```
市場ストレス指数チェック
日付: 2026-09-16
総合スコア: 79.7 / 100 (しきい値 65)
判定: 65超 -> 逆張り(買い)アクション検討

内訳:
  Fear & Greed (40%): 指数 14 (extreme fear) / 2026-09-16 -> ストレス 86.0 -> 寄与 34.4
  VIX (30%): 31.50 / 2026-09-16 -> ストレス 69.6 -> 寄与 20.9
  S&P500 200日線乖離 (30%): 5,400.00 / MA200 5,762.93 (-6.30%) -> ストレス 81.5 -> 寄与 24.4

前日終値: 5,421.49 (2026-09-15)

正規化の基準(いずれも高いほど逆張り的ストレスが強い):
  Fear & Greed: 100 - 指数 (指数0=Extreme Fear / 100=Extreme Greed)

  200日線乖離: +10%以上=0 / 0%=50 / -10%以下=100 の線形

```

## カスタマイズ

`scripts/check_market_stress.py` の冒頭定数で調整できます。

| 定数 | 既定値 | 内容 |
| --- | --- | --- |
| `DEFAULT_THRESHOLD` | `65.0` | シグナルを出すスコア |
| `WEIGHT_FNG` / `WEIGHT_VIX` / `WEIGHT_DEVIATION` | `0.40` / `0.30` / `0.30` | 各指標の重み |
| `VIX_CALM` / `VIX_PANIC` | `12.0` / `40.0` | VIXを0点・100点とみなす水準 |
| `DEVIATION_CALM` / `DEVIATION_STRESSED` | `+0.10` / `-0.10` | 200日線乖離を0点・100点とみなす水準 |
| `MA_PERIOD` | `200` | 移動平均の期間 |

- しきい値の一時的な上書きは、`Run workflow` の `threshold` 入力(環境変数 `STRESS_THRESHOLD`)で行えます。
  低い値(例: `1`)を指定すると必ず「65超」と判定されるため、**通知が実際に届くかのテスト**に使えます。
- 実行時刻は `.github/workflows/daily-market-stress-check.yml` の `cron` を変更してください(UTC指定です)。
